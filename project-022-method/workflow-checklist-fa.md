# چک‌لیست استفادهٔ دوباره از روش ۰۲۲

این فرم برای هر پروژه یک کپی تازه داشته باشد. «انجام شد» فقط با نام شاهد و نتیجه ثبت شود.

| مرحله | کار | شرط عبور / شاهد |
|---|---|---|
| شناخت | مشخصات سورس، پکیج، نسخه، دستگاه، مقصد و baseline | فهرست دامنه و پشتیبان مشخص |
| نیازها | تبدیل توضیح و علامت‌های تصویر به کارهای مستقل | تغییر، محل ثابت، پیش‌نمایش و معیار پذیرش روشن |
| طرح | تعداد خواسته‌شده، تفاوت واقعی، محتوای مرتبط | فایل نمونه و نام هر گزینه |
| QA طرح | اندازهٔ باریک/معمول، تصویر، فونت، تعامل، overflow | گزارش مرورگر + مشاهدهٔ اسکرین‌شات |
| انتخاب | پیام صریح برای هر گروه و اصلاح بعدی | ثبت شماره، نام، فایل و متن انتخاب |
| اجرا | پیاده‌سازی در ساختار اصلی و اتصال محدود | تفاوت کد قابل بررسی؛ رفتارهای حساس حفظ‌شده |
| حالت‌ها | خالی، بارگذاری، خطا، تکمیل، پنجره‌ها | فهرست حالت‌های مشاهده‌شده و مشاهده‌نشده |
| چرخش | viewport، نسبت تصویر، فضای ابزار و تبلیغ | هندسه + گوشی؛ حفظ زوم/تمرکز/پیشرفت |
| متن و برند | عنوان، همهٔ منابع فونت، پیام‌ها و اعلان | منابع واقعی داخل بسته و مسیرهای متن |
| تبلیغ/خروجی | جایزه، لغو، خطا، timeout، دوبار کلیک | تست حالت + تست واقعی مستقل در صورت مجازبودن |
| ساخت | آماده‌سازی منابع، compile، package | خروج موفق؛ stub و تست وارد APK نشده |
| بسته | دامنهٔ تفاوت، alignment، signature، hash | گزارش از همان فایل امضاشده |
| نصب | update همان پکیج و گواهی سازگار | Success؛ داده پاک نشده؛ برنامه درست باز شده |
| گوشی | همان activity در پیش‌زمینه، bounds واقعی | screenshot و گزارش محدود به خود برنامه |
| بازخورد | بازتولید، علت، اصلاح مشترک، بررسی دوباره | قبل/بعد و دامنهٔ اصلاح |
| انتشار | حساب‌ها، مجوزها، رضایت، کلید، فروشگاه | یافتهٔ باز پنهان نشده؛ مجوز انتشار مستقل |
| تحویل | روش، فایل، نسخه، تست، محدودیت و گام بعد | گزارش کامل و خلاصهٔ قابل استفاده |

## فرم ثبت انتخاب

- بخش:
- فایل پیش‌نمایش:
- شماره و نام طرح:
- پیام صریح کاربر:
- اصلاح تکمیلی:
- revision اجرا:
- نتیجهٔ گوشی و فایل شاهد:
- موارد باز:

## فرم ثبت ایراد

- شرح و علامت روی تصویر:
- صفحه / حالت / جهت / اندازه:
- نتیجهٔ فعلی و نتیجهٔ مورد انتظار:
- راه بازتولید:
- علت تأییدشده یا هنوز نامشخص:
- دامنهٔ اصلاح:
- تست و فایل قبل/بعد:

## خطاهایی که نباید تکرار شوند

- اجرای طرح پیش از انتخاب در بخشی که پیش‌نمایش خواسته شده است.
- فرض اینکه گزینهٔ اول یا حالت ویجت، انتخاب کاربر است.
- معرفی نمونهٔ مرورگری به‌عنوان نسخهٔ نصب‌شده یا Hot Reload.
- بررسی back stack قدیمی به‌جای صفحهٔ واقعاً foreground.
- کپی‌کردن مسیر دستگاه، پکیج، resource ID یا گواهی تاریخی به پروژهٔ دیگر.
- نتیجهٔ «بدون باگ» از پاس‌شدن چند تست یا یک اسکرین‌شات.
- حذف اطلاعات یا مصرف پاداش برای راحت‌ترشدن آزمون بدون مجوز.
- فراموش‌کردن الزامی که در کد هنوز مطابق خواسته اجرا نشده است.
